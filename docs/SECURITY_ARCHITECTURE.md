# Security update - 14 October 2026

Private employee document reservations and bucket policies are now implemented in migrations 021-031. Uploads are bounded to 10 MiB, content signatures are checked, paths are immutable, downloads verify the saved hash and size, and private downloads are audited. Employee account linking requires both user administration and employee-write permission, an active confirmed company account, an expected employee version and a reason. Live Storage behavior remains unverified. Migration 034 adds atomic per-user read/write/download HTTP quotas shared across app instances and company memberships, with HTTP 429 and Retry-After. Limits activate when the migration is present; pre-034 compatibility allows existing workflows and logs the missing activation. Direct Supabase RPC requests and Auth-provider throttling remain separate. RLS and RPC permission checks continue to protect direct requests.

# Security boundaries

Supabase public/publishable key remains server-configured; normal operations use the authenticated user's JWT. The app has no service-role secret. Sessions use HttpOnly, SameSite=Lax cookies and Secure cookies for HTTPS APP_URL. getUser verifies Auth before accessing active profiles. Tenant UUID headers are untrusted selectors and must pass membership and permission checks.

Business APIs authorize independently; PostgreSQL RLS is defense in depth. Security-definer functions have fixed empty search_path, qualified references, explicit permission checks and revoked internal execution grants. Company-qualified foreign keys prevent cross-company references. Database/browser errors omit sensitive values; database logging emits error codes only. Important writes and audit records share RPC transactions. Version checks reject stale employee edits. Sensitive tables have separate access policy and do not appear in list output.

Unsafe requests validate configured Origin to mitigate cookie-based CSRF; JSON requests have size and content-type checks. Supabase Auth provides provider-level rate controls; distributed per-user/IP app throttling remains outstanding. Configure Auth limits and abuse controls before exposing login/reset endpoints publicly.

`src/proxy.ts` verifies/refreshes Auth sessions and redirects signed-out business-page requests. It does not grant business permissions. Missing environment configuration shows the setup UI; API operations fail closed. The client access guard hides unfinished modules and retrieves verified active memberships before rendering integrated pages.

Remaining verification/work: live Supabase RLS/RPC tests, sessions/revocation/recovery tests, private storage/upload validation/signed downloads, at-rest identity encryption requirements, MFA policy, backup/retention rules, distributed rate limiting and prevention of reporting/salary scope leaks. Embedded PostgreSQL tests passed, and the dependency audit identified remaining high tooling-chain vulnerabilities after patching the critical Next.js issue. No claim of production security review completion is made.

Migration 040 combines active-profile, membership, permission and quota checks without bypassing independent data authorization. Provider requests have bounded timeouts; temporary Auth failures deny access with a retryable response and do not redirect to login. A project-scoped HttpOnly deny-only sign-out marker blocks late refreshed cookies; successful verified login or recovery clears it. Local logout and confirmed remote revocation are reported separately. Auth/provider outage, abort, scoped cookie cleanup and real Next proxy behavior pass fixture tests; live revocation remains unverified.
